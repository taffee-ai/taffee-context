# Migration: TypeScript to Python (draft)

**Status:** plan. Governed by decision D-007 in the umbrella `decisions.md`.

## Principle

Migrate by module, in dependency order. The TypeScript module stays in service until its Python replacement passes the same tests and produces identical output. No big-bang rewrite.

## Risks, in order

1. **Hashes must match byte for byte.** `graphHash`, `artifactHash`, `semanticConfigHash` and chunk IDs are computed from JSON. Python's `json.dumps` differs from `JSON.stringify` in key order, number formatting and escaping. Each hash function is ported with golden vectors generated by the TypeScript code. A mismatch fails the port.
2. **Parity of stored data.** A snapshot written by Python must be readable and verifiable by the TypeScript code, and the reverse, until the TypeScript code is removed.
3. **Driver behaviour.** The Neo4j Python driver must give the same transaction and timeout behaviour, including the DEF-040 timeout and the staged-then-publish sequence.

## Order

| # | Module (TypeScript today) | Python target | Gate |
|---|---|---|---|
| 1 | `ingestion/chunks/chunker.ts` | `context/ingestion/chunks.py` | Golden chunk IDs and config hash match |
| 2 | `ingestion/load/validate-snapshot.ts` (`graphHash`, `validateSnapshot`) | `validate_snapshot.py` | Golden graph hashes match |
| 3 | `service/sources.ts`, `config.ts` | `service/sources.py`, `config.py` | Same refusals (allowlist, local root, dirty tree, symlinks) |
| 4 | `service/queue.ts` | `service/queue.py` (sqlite3 from the standard library) | Same tests: dedupe, per-repo lock, lease recovery |
| 5 | `storage/neo4j/client.ts`, `schema.ts`, `ingestion/load/neo4j-loader.ts` | `storage/neo4j.py` | Stage and publish a snapshot; TypeScript verifies it |
| 6 | `ingestion/load/neo4j-semantic-loader.ts` | `ingestion/load/semantic.py` | Same lease, resume and restart behaviour |
| 7 | `ingestion/load/verify-stored.ts` | `ingestion/load/verify.py` | Same mismatch detection |
| 8 | `service/pipeline.ts`, `worker.ts`, `http.ts` | `service/` | Same job states and steps, end to end |
| 9 | `service/client.ts` and `taffee-ingest` | Python command | Same flags and output |
| 10 | `retrieval/query/*.ts` | Merged into the MCP reads (`context/serving/mcp/`) | Same tool results |
| 11 | Remove TypeScript, `package.json`, `tsconfig.json`, Node base image | | Images build without Node |

Each row ends with a parity run: the same repo through the old and new code, comparing hashes, counts and search results.

## Test strategy

- The 39 TypeScript tests are the specification. Each is ported to pytest with the same cases.
- Golden vectors for hashes and chunk IDs are generated once from the TypeScript code and committed.
- The storage contract (`docs/design/005_storage_interface/`) becomes a Python `Protocol`. The contract test suite runs against every provider.

## Toolchain

- Python 3.12, `pyproject.toml`, pinned dependencies.
- `pytest` for tests, `pyright` for type checking.
- The base image becomes Python-only: the Node layer goes.

## Done when

- The TypeScript code is removed.
- Every test that existed in TypeScript passes in Python.
- A repo ingested by Python verifies under the parity run.
- The base image builds without Node.
